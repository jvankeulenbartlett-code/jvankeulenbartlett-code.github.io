Offensive Security Home Lab

This project documents the build of my offensive security home lab using KVM virtualization, pfSense firewall routing, Kali Linux as the attacker machine, Metasploitable as a vulnerable Linux target, and a Windows Server Active Directory environment with a joined Windows client. The goal is to create a realistic lab for practising network enumeration, exploitation, Windows domain attacks, and post-exploitation workflows inside an isolated environment.

🗓 Mar 2026 ⚙ KVM 🛡 pfSense 🐉 Kali Linux 🧪 Metasploitable 🪟 Windows Server 🏢 Active Directory 💻 Windows Client

Project Overview

The lab is designed to simulate a small enterprise-style environment where an attacker machine can safely interact with both Linux and Windows targets. pfSense acts as the firewall and gateway for the internal network, while Kali Linux provides the offensive tooling used for host discovery, service enumeration, exploitation, and later Active Directory attack paths.

By adding Windows Server and a domain-joined Windows client, the lab becomes more realistic and useful for learning enterprise-focused offensive security techniques such as SMB enumeration, LDAP discovery, Kerberos-related attacks, BloodHound collection, and lateral movement concepts.

Lab Architecture

The environment uses pfSense as the gateway between the default NAT network and an isolated internal lab segment. All attacker and target systems live on the internal network, allowing safe communication without exposing the host operating system or home network to lab activity.

Virtualization Platform

The environment is hosted on a Linux system using KVM/QEMU virtualization and managed through virt-manager. This makes the lab easy to snapshot, rebuild, and expand as new machines and services are added.

  • Hypervisor: KVM / QEMU
  • Management interface: virt-manager
  • Firewall: pfSense
  • Attacker: Kali Linux
  • Linux target: Metasploitable
  • Windows infrastructure: Windows Server + Active Directory
  • Client system: Windows 10 / 11 joined to the domain
virt-manager showing the full lab environment and virtual machine inventory.

pfSense Firewall and Network Configuration

pfSense provides routing, DHCP, and internal network control for the lab. The WAN interface receives an address from the default NAT network, while the LAN interface is configured on the internal segment as 192.168.50.1/24.

  • WAN: vtnet0 on the default NAT network
  • LAN: vtnet1 on lab-net
  • LAN IP: 192.168.50.1/24
  • DHCP range: 192.168.50.100 - 192.168.50.200

Linux Target: Metasploitable

Metasploitable is included as an intentionally vulnerable Linux target for practising discovery, service enumeration, exploitation, and post-exploitation workflows. It provides a controlled way to test tools and offensive methodology without attacking production systems.

Metasploitable target machine connected to the isolated lab network.

Windows Server and Active Directory

A Windows Server system is included to provide enterprise-style infrastructure through Active Directory, DNS, and domain services. This makes the lab far more realistic and supports future testing of Windows-focused enumeration and authentication workflows.

  • Role: Domain Controller
  • Services: Active Directory, DNS, domain management
  • Use cases: user and computer management, domain joins, Windows attack-path practice
Windows Server VM running as part of the internal lab environment.
Active Directory Users and Computers showing the domain structure and managed objects.

Windows Client

A Windows client machine is used to represent a normal domain workstation inside the environment. Once joined to the domain, it becomes useful for testing Windows enumeration, credential collection paths, domain trust relationships, and workstation-focused attack scenarios.

  • Role: Domain-joined workstation
  • Purpose: simulate a normal enterprise endpoint
  • Future uses: SMB testing, PowerShell activity, lateral movement concepts, AD attack paths
Windows client machine connected to the internal lab network.

Planned Offensive Security Workflows

With both Linux and Windows systems inside the same isolated environment, the lab can support multiple offensive security workflows ranging from basic host discovery to enterprise-style domain enumeration.

  • Host discovery with Nmap
  • Service enumeration against Linux and Windows systems
  • Web testing against vulnerable services
  • SMB, LDAP, and Kerberos-related enumeration
  • Future BloodHound collection and Active Directory attack-path mapping
# Host discovery nmap -sn 192.168.50.0/24 # Service discovery nmap -sV 192.168.50.X # Future Windows-focused enumeration smbclient -L //TARGET -N ldapsearch bloodhound-python
Initial host discovery and service enumeration from the Kali attacker machine.

Outcome

This lab provides a practical foundation for developing offensive security skills in a safe, controlled, and expandable environment. It combines network infrastructure, Linux targets, and Windows domain services into a single portfolio project that can grow into future writeups on exploitation, post-exploitation, and enterprise attack paths.
